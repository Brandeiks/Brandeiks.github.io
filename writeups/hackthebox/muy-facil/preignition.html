// 01

Reconocimiento

1
CONTEXTO DE LA MÁQUINA

Preignition es una máquina Linux de dificultad Very Easy centrada en la enumeración web básica: fuzzing de directorios para descubrir un panel de administración y el peligro de dejar credenciales por defecto en una aplicación mal configurada. Un recorrido limpio por la metodología inicial de cualquier auditoría web.

2
COMPROBAR CONECTIVIDAD

Antes de nada confirmamos que llegamos a la máquina (10.129.2.4) con unos paquetes ICMP. El TTL de la respuesta, de paso, suele delatar el sistema operativo (~64 = Linux).

PING
$ ping 10.129.2.4 -c3
3
ESCANEO DE PUERTOS CON NMAP

Escaneamos con detección de versión (-sV). Solo hay un servicio relevante: un servidor web nginx 1.14.2 en el puerto 80.

NMAP
$ nmap -sV 10.129.2.4
PORT STATE SERVICE VERSION
80/tcp open http nginx 1.14.2

// UN ÚNICO SERVICIO WEB

Con solo el puerto 80 abierto, toda la superficie de ataque es la aplicación web. El siguiente paso lógico es enumerar lo que esconde: directorios y archivos no enlazados desde la página principal.

// 02

Enumeración web · Dir busting

4
FUZZING DE DIRECTORIOS CON GOBUSTER

Usamos gobuster en modo dir para probar nombres de un diccionario (common.txt) contra el servidor y descubrir rutas ocultas. Con -x php le pedimos que pruebe también cada nombre con extensión .php, ya que es una app PHP.

GOBUSTER
$ gobuster dir -u http://10.129.2.4 -w /usr/share/wordlists/dirb/common.txt -x php
===============================================================
[+] Url: http://10.129.2.4
[+] Wordlist: /usr/share/wordlists/dirb/common.txt
[+] Extensions: php
===============================================================
/admin.php (Status: 200) [Size: 999]
===============================================================

// HALLAZGO: /admin.php

Gobuster descubre /admin.php con código 200 OK: la página existe y es accesible, aunque no esté enlazada en ningún sitio. Un nombre así —un panel de administración— es justo lo que buscábamos.

// 03

Explotación · Credenciales por defecto

5
EL PANEL «ADMIN CONSOLE LOGIN»

Abrimos http://10.129.2.4/admin.php en el navegador y nos recibe un formulario de inicio de sesión: «Admin Console Login». El objetivo de la máquina es demostrar el riesgo de no cambiar la configuración de fábrica, así que —antes de ruido como SQLi o fuerza bruta— probamos las credenciales por defecto más típicas de la industria.

CAMPO VALOR PROBADO
Usernameadmin
Passwordadmin
6
ACCESO Y FLAG

Las credenciales admin:admin funcionan a la primera. El panel interno nos da la bienvenida y muestra directamente la flag:

6483bee07c1c1d57f14e5b0717503c73

// FLAG

6483bee07c1c1d57f14e5b0717503c73 — obtenida sin exploits ni escalada: basta descubrir /admin.php por fuerza de diccionario y usar las credenciales de fábrica admin:admin.

// LECCIÓN Y MITIGACIÓN

Dos malas prácticas encadenadas: dejar un panel de administración accesible y no cambiar las credenciales por defecto. La mitigación es inmediata — forzar contraseñas fuertes y únicas en el primer arranque, restringir el acceso a los paneles admin (por IP, VPN o autenticación adicional), no exponerlos a Internet, y añadir límites de intentos y MFA. El dir busting es trivial para un atacante, así que «oculto» nunca es «protegido».

// 04

Referencia de Comandos

ping
ping <ip> -c3
Envía paquetes ICMP para comprobar conectividad con el objetivo. El TTL de la respuesta ayuda a intuir el SO (~64 Linux, ~128 Windows).
  • -c3 — envía solo 3 paquetes y termina
nmap
nmap -sV <ip>
Escanea los puertos más comunes y detecta la versión de cada servicio. Aquí identifica nginx 1.14.2 en el puerto 80.
  • -sV — detección de versión del servicio
  • -p- — todos los puertos (si quieres ir más allá de los 1000 comunes)
gobuster dir
gobuster dir -u <url> -w <wordlist> -x php
Fuerza bruta de directorios y archivos: prueba cada palabra del diccionario contra el servidor y reporta las que devuelven respuesta. Descubre /admin.php.
  • -u — URL objetivo
  • -w — diccionario (p. ej. dirb/common.txt)
  • -x php — prueba también la extensión .php
  • -t — número de hilos (velocidad)
Credenciales por defecto
admin : admin
Antes de ataques ruidosos, siempre se prueban las credenciales de fábrica. En paneles mal configurados (admin:admin, root:root, admin:password) suelen seguir activas.
  • admin:admin — la combinación que abre este panel
  • root / password / 12345 — otras típicas a probar

// 05

Glosario

Dir busting / fuzzing de directorios
Técnica de enumeración web que prueba nombres de un diccionario contra un servidor para descubrir directorios y archivos no enlazados (paneles admin, backups, archivos de configuración). Herramientas típicas: gobuster, ffuf, dirsearch, feroxbuster.
gobuster
Herramienta en Go para fuerza bruta de URLs (modo dir), subdominios (dns) o vhosts. Rápida y sencilla; con -x prueba extensiones concretas y con -w carga el diccionario. Devuelve el código de estado de cada acierto.
Credenciales por defecto
Usuario y contraseña que trae un software «de fábrica» (admin:admin, root:root…). Si no se cambian en la instalación, son una de las puertas de entrada más fáciles y comunes. Es una forma de autenticación débil.
nginx
Servidor web y proxy inverso muy extendido. Aquí sirve la aplicación PHP en el puerto 80. La versión que reporta nmap (1.14.2) es solo informativa: la vulnerabilidad no está en nginx, sino en la app que aloja.
Código de estado HTTP 200
Respuesta «OK»: el recurso existe y el servidor lo devuelve. En dir busting es la señal de un acierto directo; otros útiles son 301/302 (redirección), 403 (existe pero prohibido) y 401 (requiere autenticación).
Wordlist / common.txt
Diccionario de nombres probables que usan las herramientas de fuzzing. /usr/share/wordlists/dirb/common.txt viene en Kali/Parrot y reúne rutas habituales (admin, login, backup…). SecLists ofrece listas mucho más completas.
Panel de administración
Interfaz web privilegiada para gestionar una aplicación. Suele ser el objetivo prioritario de un atacante: comprometerlo da control sobre la app. Por eso nunca debe exponerse sin protección ni con credenciales por defecto.
Autenticación débil
Cualquier mecanismo de login fácil de superar: credenciales por defecto o adivinables, ausencia de límite de intentos, falta de MFA. Es la categoría de la que depende por completo esta máquina.
