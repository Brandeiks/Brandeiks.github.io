// 02

SSTI y escape de sandbox

3
CONFIRMAR EL MOTOR DE PLANTILLAS
SSTI PROBE
$ curl -s -X POST 'http://10.129.97.64/' --data-urlencode 'email={{7*7}}' --data-urlencode 'action=Submit'
Error: Parse error on line 1: {{7*7}}
Expecting 'ID', 'STRING', ... at Parser.parseError
(/root/Backend/node_modules/handlebars/...)

// DOS DATOS CLAVE EN UN SOLO ERROR

El error no es de Jinja2 (que sí evaluaría 7*7): es de Handlebars, que no acepta expresiones aritméticas en los mustaches y hay que atacarlo con un gadget distinto. Además, la traza revela la ruta /root/Backend: la app corre como root, así que cualquier RCE será directamente root.

4
GADGET DE ESCAPE: CONSTRUCTOR → FUNCTION → EXECSYNC

Handlebars sanitiza las expresiones normales, pero su sandbox se puede escapar navegando desde un string literal hasta su constructor (Function) con lookup, y ejecutando el código inyectado con .apply.

HANDLEBARS GADGET
# cadena de #with que llega a String.prototype.constructor (Function)
# e inyecta: return process.mainModule.require('child_process').execSync('CMD').toString()
uid=0(root) gid=0(root) groups=0(root)

// OJO CON EL PAYLOAD

Handlebars interpreta |, { y } dentro de la plantilla: hay que evitar esos caracteres en el CMD que se inyecta (nada de pipes ni llaves directamente).

5
LEER LA FLAG
FLAG
# CMD = 'cat /root/flag.txt' dentro del mismo gadget
[flag oculta]

// FLAG

[flag oculta] — única flag del reto: la aplicación corre como root y no hay más usuarios con shell en /etc/passwd, así que no hace falta escalar privilegios.

Referencia Comandos

SSTI probe
{{7*7}}
Prueba clásica para detectar inyección de plantillas; el mensaje de error (o su ausencia) delata el motor exacto.
lookup (Handlebars)
{{lookup objeto "propiedad"}}
Helper que accede a una propiedad de un objeto por su nombre, usado en el gadget para llegar al constructor.
child_process.execSync
require('child_process').execSync('comando').toString()
API de Node.js para ejecutar un comando del sistema de forma síncrona y recoger su salida como texto.

// 04

Glosario

SSTI — Server-Side Template Injection
Vulnerabilidad donde entrada del usuario se compila como parte de una plantilla, en lugar de insertarse como dato. Según el motor, puede escalar hasta ejecución de código.
Handlebars
Motor de plantillas lógicas (sin expresiones arbitrarias) muy usado en Node.js. Su sandbox impide evaluar expresiones directamente, pero es vulnerable a gadgets que navegan el prototipo de JavaScript.
Escape de sandbox
Técnica que rodea las restricciones de un entorno limitado (aquí, el motor de plantillas) accediendo a objetos del lenguaje subyacente (como Function) a través de rutas no anticipadas.
Function constructor
En JavaScript, Function("código") crea y ejecuta una función a partir de una cadena de texto — equivalente a un eval con otra sintaxis, y objetivo habitual de los gadgets de escape.
