// 01

Reconocimiento y vhost

1
ESCANEO Y PRIMERA PETICIÓN
BASH
$ sudo nmap -sT -sV -p22,80 10.129.1.27
$ curl -s -o /dev/null -w '%{http_code}\n' http://10.129.1.27/
PORT STATE SERVICE VERSION
22/tcp closed ssh
80/tcp open http nginx 1.14.2
302

// NOTA

Un 302 sin cuerpo visible al pedir la IP directamente, con nginx de por medio, es la huella clásica de un servidor configurado por nombre de host virtual (vhost): la config por defecto redirige todo lo que no coincida con ningún server_name conocido.

2
RESOLVER EL VHOST
BASH
$ echo '10.129.1.27 ignition.htb' | sudo tee -a /etc/hosts
$ curl -s -o /dev/null -w '%{http_code} %{size_download}\n' http://ignition.htb/
200 26113

// ENUMERACIÓN DESBLOQUEADA

Con el nombre correcto en /etc/hosts, la petición pasa de un 302 vacío a un 200 con 26 KB: una tienda Magento. Sin este paso no hay nada que enumerar.

// 02

Panel Magento y login

3
LOCALIZAR EL BACKEND
BASH
$ curl -s -o /dev/null -w '%{http_code}\n' http://ignition.htb/admin
200

/admin es la ruta por defecto del backoffice de Magento. El HTML del formulario revela dos detalles clave: los campos se llaman login[username] y login[password] (no username/password a secas), y hay un form_key oculto que actúa como token CSRF — sin él, el POST se rechaza o se ignora.

4
LOGIN AUTOMATIZADO Y LECTURA DE LA FLAG
PYTHON
$ python3 login.py
# 1. GET /admin, extraer form_key con una regex
# 2. POST con login[username]/login[password] + form_key + Referer
# 3. buscar hashes de 32 hex en la respuesta (timeout 120s: el dashboard tarda)
Congratulations, your flag is: [flag oculta]
# también aparece da332d712f3215b9b94bfa268c398323 — es el "identity" de una notificación, NO la flag

// OJO CON EL SEÑUELO

El dashboard de Magento muestra dos cadenas de 32 caracteres hexadecimales: solo la que va precedida del texto «Congratulations, your flag is:» es la flag real. La otra es el identificador interno de una notificación del panel y tiene la misma forma, pero no es el objetivo.

// FLAG

[flag oculta] — en el bloque Advanced Reporting del dashboard de Magento, tras autenticarse como admin. Tiempo total: ~15 minutos.

// 03

Referencia Comandos

curl -w
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' <URL>
Comprueba el código de estado y el tamaño de la respuesta sin volcar el cuerpo, ideal para detectar redirecciones.
  • -o /dev/null → Descarta el cuerpo de la respuesta.
  • -w → Formato de salida con variables (código, tamaño, tiempo...).
/etc/hosts
echo '<IP> dominio' | sudo tee -a /etc/hosts
Resuelve manualmente un vhost que no existe en ningún DNS público, imprescindible cuando el servidor exige Host:.
requests.Session()
s = requests.Session(); s.get(...); s.post(...)
Mantiene las cookies entre peticiones automáticamente, necesario para cualquier login web scripteado.
  • form_key → Token CSRF de Magento; se extrae del GET inicial y se reenvía en el POST.
  • timeout → Generoso (120s) porque el dashboard de Magento es pesado.

// 04

Glosario

Virtual host (vhost)
Mecanismo de nginx/Apache para servir varios sitios bajo la misma IP, distinguiéndolos por la cabecera Host. Sin el nombre correcto, el servidor no sabe qué aplicación mostrar.
Magento
Plataforma de comercio electrónico en PHP, muy extendida y con un panel de administración (/admin por defecto) que concentra pedidos, catálogo y configuración.
form_key (token CSRF)
Valor único generado por Magento en cada formulario para evitar peticiones falsificadas entre sitios. Hay que leerlo del GET y reenviarlo en el POST para que el login se procese.
Credenciales por defecto
Usuario y contraseña que vienen de fábrica o de una instalación rápida y nunca se cambian. Es la causa más común de compromiso en paneles de administración expuestos.
Advanced Reporting
Módulo del dashboard de Magento con estadísticas de la tienda. En esta máquina, el reto usa ese bloque como lugar para mostrar la flag tras un login correcto.
